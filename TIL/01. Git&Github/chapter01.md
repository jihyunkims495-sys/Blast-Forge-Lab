# 1장 1강: Git 동작 원리와 3영역 모델
## 핵심 정리
---
1. Git은 분산 버전 관리 시스템(DVCS)으로, 모든 참여자가 전체 이력을 로컬에 보유합니다.
2. Git과 GitHub는 다릅니다. Git은 도구, GitHub는 서비스입니다.
3. Git은 Working Directory → Staging Area → Repository 3영역 구조로 파일 변화를 추적합니다.
4. 커밋은 diff가 아닌 스냅샷 방식으로 저장되며, SHA 해시로 고유하게 식별됩니다.
5. HEAD는 현재 위치를, 브랜치 포인터는 최신 커밋을 가리킵니다.

### 1. 버전 관리의 필요성과 Git의 등장
---
버전 관리(Version Control)란?
- 버전 관리는 파일의 변화를 시간 순서로 기록하고, 필요할 때 특정 시점으로 되돌아갈 수 있게 해주는 시스템
- 과거에는 `final.py`, `final_v2.py`, `final_진짜최종.py`처럼 파일 이름으로 버전을 관리했었으나, github은 협업 환경에서 누가 무엇을 언제 바꿨는지까지 추적할 수 있다.

AI 서비스에서  Git이 특히 중요한 이유?
- Git은 재현성(reproducibility)을 보장하는 핵심 도구
- AI 서비스에서는 데이터 전처리, 모델 학습, 추론, API 등 다양한 코드가 함께 개발
- 작은 코드 변경 하나가 모델의 동작이나 서비스 결과에 영향을 줄 수 있기 때문에, 변경 이력을 관리하고 필요할 때 이전 버전으로 복구가 가능!

[중요!] Git과 GitHub는 같은 것 아닌가요?
- Git은 로컬 컴퓨터에서 동작하는 버전 관리 도구이고, GitHub는 Git 저장소를 온라인에서 호스팅해 주는 서비스
- Git 없이는 GitHub를 사용할 수 없지만, Git은 GitHub 없이도 혼자 사용할 수 있음
- 비개발자와 비전공자들에게는 Github이 생소하지만, googledrive 같이 코드를 공유하고 sns처럼 코드를 공유하고 바이럴 할 수 있는 공간입니다. 

### 2. 분산 버전 관리(DVCS)와 Git 구조
---
중앙 집중식 vs 분산 버전 관리
- Git은 분산 버전 관리 방식을 취한다. 모든 개발자가 전체 이력을 로컬에 복사하고 있어 속도가 빠르고 오프라인에서도 작업이 가능
DAG 구조로 이해하는 커밋 관계
- Git의 커밋 이력은 단순한 선형 구조가 아니라 방향성 비순환 그래프(DAG, Directed Acyclic Graph) 구조
- 각 커밋(COMMIT)은 이전 커밋을 가리키는 포인터(HEAD)를 갖고 있어, 브랜치(작업 흐름을 여러 갈래로 나누는 것,BRANCH)가 생기거나(CREATE) 병합(MERGE)될 때 그래프가 분기하거나 합쳐진다. 이 구조 덕분에 여러 사람이 동시에 다른 작업을 진행하고, 나중에 하나로 합칠 수 있다

### 3. Git의 3영역 모델
---
1. Working Directory (작업 디렉터리) : 실제 편집 중인 파일들이 있는 공간
2. Staging Area(Index/스테이징 영역) : 다음 커밋에 포함할 변경들을 모아두는 임시 공간
3. Repository (저장소) : 커밋이 영구 저장되는 공간 (.git)

#### 터미널에서의 git 명령어 기초
---
1. git status : '조회'기능으로 각영역에 어떤 변경이 있는지 현재 상태를 볼 수 있음
2. git add : '스테이징'단계로 변경 파일을 다음 커밋 대상으로 올림
3. git commit : '저장'단계로 스테이징된 변경들을 '스냅샷'으로 영구 저장
4. git push : 커밋된 스냅샷을 Github로 내보내기
5. git stash : 임시저장
6. git pull : Github에서 내 컴퓨터(Local)로 받는 작업
7. git remote : 내 로컬 Git 저장소와 연결된 원격 저장소(GitHub)의 정보를 확인·관리
8. git branch : 분기(Branch) 생성- 작업 공간 생성
9. git clone : Github에서 내 컴퓨터(Local)로 받는 작업으로 복제 떠오는 것

[중요!] 스냅샷 기반 커밋 원리
- Git은 파일의 차이(diff)가 아닌 **스냅샷(snapshot)**을 저장
- 커밋 시점의 모든 파일 상태를 하나의 사진처럼 찍어두는 방식
- 변경이 없는 파일은 이전 스냅샷을 재사용하므로 용량 낭비가 없다는 장점

[중요!] HEAD, 브랜치 포인터, SHA 해시
- HEAD: 현재 작업 중인 커밋 또는 브랜치를 가리키는 포인터!
- 브랜치 포인터: 특정 커밋을 가리키는 이름표로, 새 커밋이 생기면 자동으로 앞으로 이동
- SHA 해시: 각 커밋에 부여되는 40자리 고유 ID로, 내용을 기반으로 생성되므로 내용이 조금만 바뀌어도 해시가 완전히 달라져, 이력 변조를 사실상 탐지할 수 있음
