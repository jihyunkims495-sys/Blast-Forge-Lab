## 1. What — 무엇을 배웠는가?

### 핵심 개념

- `try / except / else / finally`를 이용한 예외 처리의 기본 실행 흐름
- `raise`를 이용해 예외를 의도적으로 발생시키는 구조
- `ValueError`, `IndexError`, `ZeroDivisionError`처럼 실행 중 발생하는 예외와 `SyntaxError`, `IndentationError` 같은 문법 오류의 차이
- `except ValueError as e`에서 `e`는 발생한 예외 객체를 받아두는 변수라는 점
- 사용자 정의 예외는 `Exception`을 상속해 만들 수 있다는 점
- VS Code Debugger의 Breakpoint, Variables, Step Over / Into / Out, Continue 사용법
- Traceback은 맨 아래의 최종 예외부터 확인한 뒤 문제가 발생한 줄과 호출 경로를 역으로 추적한다는 점

### 핵심 코드

```python
try:
    index = int(input("메뉴 번호를 입력하세요: "))
    result = menu[index]
except ValueError as e:
    print("숫자를 입력해야 합니다.", e)
except IndexError as e:
    print("존재하지 않는 메뉴 번호입니다.", e)
else:
    print(result)
finally:
    print("메뉴 조회를 종료합니다.")
```

```python
class LoginError(Exception):
    pass


def login(user_id):
    if user_id != "admin":
        raise LoginError("아이디가 일치하지 않습니다.")
    return "로그인 성공"
```

### 오늘 수행한 실습

- 메뉴 리스트에서 사용자가 입력한 인덱스로 값을 조회하며 `ValueError`와 `IndexError`가 발생하는 위치를 구분했다.
- `raise`와 사용자 정의 예외의 기본 구조를 확인했다.
- VS Code에서 Breakpoint를 걸고 Variables 패널을 보면서 변수 값의 변화를 확인했다.
- Step Over / Step Into / Step Out을 사용해 실행 흐름을 따라가 봤다.
- `ZeroDivisionError`가 발생한 코드의 Traceback을 읽어봤다.

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

- 프로그램은 예상하지 못한 입력이나 상황에서도 바로 멈추지 않고 적절하게 대응해야 한다.
- 예외 처리를 하면 문제가 생겼을 때 어떤 방식으로 대응할지 코드로 정할 수 있다.
- 디버깅은 코드가 왜 잘못됐는지 실행 흐름과 변수 상태를 직접 확인하는 데 필요하다.
- Traceback을 읽을 수 있어야 오류 메시지를 보고 문제 위치를 스스로 찾아갈 수 있다.

### 내 생각

> `try-except`는 예외 케이스를 처리하는 Python 키워드 구조라고 이해했다. `try` 안에는 예외가 발생할 수 있는 코드를 넣고, `except`에서 발생한 예외를 처리하면서 프로그램의 실행을 이어가는 데 목적이 있다. 아직 `raise`는 정확히 내 것이 된 느낌은 아니고 내일이면 잊어버릴 것 같아서 반복학습이 필요하다. 다만 `return`이 함수를 정상적으로 끝낸다면, `raise`는 예외를 발생시키면서 정상 흐름을 끊는다는 차이는 조금 이해했다.

---

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. `try`에서 예외가 발생할 가능성이 있는 코드를 실제로 실행한다.
2. 예외가 발생하면 `try`의 남은 실행을 멈추고 맞는 `except`로 이동한다.
3. 예외가 없으면 `else`가 실행될 수 있다.
4. `finally`는 성공 여부와 관계없이 마지막에 실행된다.
5. `raise`를 만나면 예외를 직접 발생시키고 정상 실행 흐름을 중단한다.
6. 문제가 생겼을 때는 Traceback과 Debugger를 이용해 어느 줄에서 어떤 값 때문에 문제가 생겼는지 추적한다.

### 내 말로 설명하기

> 예외 처리는 "문제가 생기지 않게 만드는 것"이라기보다 "문제가 생겼을 때 프로그램이 어떻게 대응할지 정해두는 것"에 가깝다. `try`에서 실제 코드를 돌려보고, 문제가 생기면 `except`가 받아서 처리한다. 디버깅은 그 문제를 처리하는 코드가 아니라 왜 문제가 생겼는지 찾아가는 과정이다.
