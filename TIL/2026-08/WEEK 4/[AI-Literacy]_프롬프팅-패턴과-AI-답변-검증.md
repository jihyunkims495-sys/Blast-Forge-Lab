# [AI Literacy] 3장 1강: 프롬프팅 패턴 이해

## 학습 목표

- Zero-shot, Few-shot의 차이와 CoT(Chain-of-Thought)의 기본 개념을 이해한다.
- Role, Goal, Context/Constraint를 조합해 구조적인 프롬프트를 설계할 수 있다.
- Few-shot, 출력 형식 지정, 컨텍스트 설계를 결합해 결과 품질을 높이는 방법을 이해한다.

## 사용 프로그램

- ChatGPT
- Gemini

## 1. Zero-shot과 Few-shot

### 1.1 Zero-shot Prompting

예시를 제공하지 않고 지시문만으로 작업을 요청하는 방식이다.

예:

```text
다음 고객 리뷰의 핵심 키워드를 추출하고 감정을 긍정/중립/부정으로 분류해줘.
```

### 장점

- 빠르고 간단하다.
- 번역, 요약, 간단한 분류처럼 요구사항이 명확한 작업에 적합하다.

### 한계

- 출력 형식이나 판단 기준이 모호하면 결과가 흔들릴 수 있다.
- 복잡한 업무에서는 사용자의 의도를 충분히 반영하지 못할 수 있다.

> Zero-shot 자체가 환각의 직접 원인은 아니다. 환각은 모델의 생성 특성과 정보 부족, 모호한 맥락, 최신성 부족 등 여러 요인에서 발생한다.

### 1.2 Few-shot Prompting

소수의 입력-출력 예시를 프롬프트에 함께 제공해 원하는 패턴을 보여주는 방식이다.

```text
예시 1
입력: 배송이 늦고 서비스가 엉망이에요.
출력: [키워드: 배송 지연, 서비스] / [감정: 부정]

예시 2
입력: 마감이 깔끔하고 색상이 마음에 들어요.
출력: [키워드: 마감, 색상] / [감정: 긍정]

실제 입력:
포장은 괜찮았지만 설명서가 너무 복잡했어요.
```

Few-shot은 모델의 가중치를 다시 학습시키는 것이 아니라, 현재 대화의 컨텍스트 안에서 예시 패턴을 참고하게 하는 **In-Context Learning** 방식이다.

### 적합한 상황

- 특정 출력 형식 유지
- 일정한 톤앤매너
- 분류 기준 통일
- 코드 스타일 통일
- 반복 업무 템플릿화

### 주의점

예시 자체가 잘못되면 모델도 잘못된 패턴을 따라갈 수 있다.

## 2. Chain-of-Thought(CoT)와 단계적 추론

CoT는 복잡한 문제를 한 번에 답하지 않고 여러 단계로 분해해 풀도록 유도하는 프롬프팅 개념이다.

예:

```text
조건을 먼저 정리하고, 필요한 계산을 순서대로 수행한 뒤 최종 답만 명확히 제시해줘.
```

### 핵심 목적

- 복잡한 문제를 작은 단계로 분해
- 조건 누락 감소
- 계산이나 논리의 흐름 구조화
- 최종 답변의 일관성 향상

> 중요한 보정: 고급 추론 모델은 내부적으로 추론 과정을 수행할 수 있지만, 사용자가 모델의 숨겨진 내부 사고과정 전체를 볼 필요는 없다. 실무에서는 **핵심 근거, 계산 과정, 검증 가능한 단계만 간결하게 요구하는 방식**이 더 적절하다.

### Zero-shot CoT

```text
이 문제를 해결할 때 필요한 조건을 단계별로 정리하고 계산한 뒤 최종 답을 제시해줘.
```

### Few-shot CoT

문제 해결 방식의 예시까지 함께 제공한다.

```text
[예시]
질문: 매출 100억, 영업이익 20억이면 영업이익률은?
풀이 요약: 20 / 100 × 100 = 20%
최종 답: 20%

[질문]
...
```

### 학습 포인트

CoT의 핵심은 장황한 사고과정을 길게 쓰게 만드는 것이 아니라, **복잡한 문제를 구조적으로 분해하게 하는 것**이다.

## 3. RGC 프레임워크

RGC는 프롬프트를 구조적으로 설계하기 위한 실무형 틀이다.

### Role

AI가 어떤 관점에서 답해야 하는지 지정한다.

```text
너는 10년 차 CRM 마케터다.
```

### Goal

무엇을 해야 하는지 행동 중심으로 명확히 적는다.

```text
20대 신규 고객을 위한 재구매 유도 메시지 5개를 작성해줘.
```

### Context / Constraint

업무 배경과 반드시 지켜야 할 조건을 지정한다.

```text
- 브랜드 톤: 친근하지만 과장 금지
- 60자 이내
- 할인율 언급 금지
- 표 형태로 출력
```

### RGC 예시

```text
Role:
너는 이커머스 CRM 마케팅 전문가다.

Goal:
장바구니 이탈 고객에게 보낼 푸시 메시지 5개를 작성해줘.

Context / Constraint:
- 타깃: 20~30대 여성
- 50자 이내
- 지나친 긴급성 표현 금지
- 각 문구의 의도를 한 줄로 설명
- Markdown 표로 출력
```

> Role을 부여한다고 모델 내부의 특정 전문 영역이 물리적으로 분리되는 것은 아니다. 역할 설정은 주로 답변의 관점, 어휘, 톤, 우선순위를 조정하는 데 도움이 된다.

## 4. 출력 형식 통제

AI 결과를 실제 업무에 바로 활용하려면 내용뿐 아니라 **형식**도 지정해야 한다.

### Markdown

```text
표 형태로 정리해줘.
```

### JSON

```json
{
  "keyword": "배송 지연",
  "sentiment": "negative"
}
```

### 출력 제약의 장점

- 자동화에 연결하기 쉬움
- 후처리 감소
- 팀 내 일관성 향상
- 데이터 파이프라인에 활용 가능

> 형식을 지정한다고 환각이 자동으로 사라지는 것은 아니다. 형식 통제와 사실 검증은 별개의 문제다.

## 5. Context Engineering

컨텍스트 엔지니어링은 한 문장의 프롬프트를 다듬는 것을 넘어, 모델이 판단할 때 참고해야 할 전체 정보 환경을 설계하는 것이다.

예를 들어 다음 요소를 함께 관리한다.

- 역할
- 목표
- 업무 배경
- 참조 문서
- 과거 대화
- 금지 조건
- 출력 형식
- 사용 가능한 도구
- 최신 데이터

### Prompt Engineering과 차이

```text
Prompt Engineering
→ 한 번의 지시문을 잘 쓰는 것

Context Engineering
→ 모델이 참고하는 전체 정보 환경을 설계하는 것
```

# [AI Literacy] 3장 2강: AI 답변 검증 방법

## 학습 목표

- AI 출력물의 정확성과 신뢰성을 검증하는 기본 프로세스를 이해한다.
- 출처, 숫자, 고유명사, 인용구를 교차 검증할 수 있다.
- AI 결과를 그대로 신뢰하지 않고 외부 근거를 통해 검증하는 습관을 익힌다.

## 사용 프로그램

- ChatGPT
- Gemini
- Perplexity

---

## 1. 왜 AI 답변 검증이 필요한가

LLM은 사실 데이터베이스를 그대로 조회하는 시스템이 아니라, 주어진 문맥을 바탕으로 다음에 올 토큰을 예측하며 문장을 생성한다.

따라서 자연스럽고 자신감 있는 문장이라도 사실과 다를 수 있다.

### Hallucination

AI가 존재하지 않는 정보나 잘못된 수치를 사실처럼 생성하는 현상이다.

대표적으로 위험한 항목은 다음과 같다.

- 최신 뉴스
- 숫자 및 통계
- 연도
- 논문 제목
- 법률 조항
- 인물 이력
- 기업 정보
- 출처 링크
- 인용구

> AI가 틀린 답을 생성한다고 해서 의도적으로 거짓말하는 것은 아니다. 생성 모델의 확률적 특성에서 발생하는 오류다.

---

## 2. SIFT 프레임워크

정보 검증 시 사용할 수 있는 대표적인 구조다.

### S — Stop

정보를 바로 믿거나 공유하지 않는다.

### I — Investigate the Source

출처가 실제 존재하는지, 신뢰할 만한 기관인지 확인한다.

### F — Find Better Coverage

다른 독립적인 출처에서도 같은 내용을 확인할 수 있는지 비교한다.

### T — Trace to the Original Context

2차 요약이나 AI 답변만 보지 않고 원문, 원 보고서, 원 통계를 직접 확인한다.

### 한 줄 구조

```text
멈춘다 → 출처를 본다 → 다른 출처와 비교한다 → 원문까지 간다
```

---

## 3. Micro Fact-Check

긴 답변 전체를 한 번에 검증하기 어렵기 때문에 위험도가 높은 요소를 따로 뽑아 확인한다.

### 반드시 우선 검증할 항목

1. 숫자
2. 날짜와 연도
3. 고유명사
4. 법률/정책
5. 논문 및 연구
6. 출처 URL
7. 직접 인용문

### 예

AI 답변:

```text
A기업의 2025년 시장점유율은 37.2%다.
```

검증 방법:

```text
1. 37.2%라는 숫자를 분리한다.
2. 조사 기관 이름을 확인한다.
3. 공식 보고서 또는 공신력 있는 기사에서 같은 수치가 있는지 확인한다.
4. 조사 기준과 기간이 같은지 확인한다.
```

숫자가 같아도 **기간, 지역, 분모, 조사 기준**이 다르면 다른 데이터일 수 있다.

---

## 4. 다중 모델 교차 검증

여러 AI 모델에 같은 질문을 던져 결과를 비교하는 것은 오류를 발견하는 데 도움이 될 수 있다.

하지만 다음 원칙이 중요하다.

```text
AI A가 말함
+ AI B도 말함
= 사실 확정
```

은 아니다.

여러 모델이 동일한 잘못된 웹 문서나 유사한 학습 데이터를 참고했을 수도 있기 때문이다.

### 올바른 구조

```text
AI 초안
→ 다른 모델로 반론/누락 확인
→ 웹/공식 문서 확인
→ 원문 확인
→ 인간이 최종 판단
```

### 모델의 역할은 고정하지 말 것

플랫폼별 기능은 계속 바뀌므로 "ChatGPT는 초안용, Gemini는 최신 정보용, Perplexity는 검증용"처럼 영구적인 고정 역할로 외우는 것은 위험하다.

실제 업무에서는 **현재 사용할 수 있는 웹 검색, 출처 표시, 파일 분석, 데이터 분석 기능을 확인한 뒤 역할을 배정**하는 것이 더 정확하다.

---

## 5. Fact Verification Prompting

AI에게 답을 바로 다시 쓰게 하기보다, 검증 작업을 분리해 요청할 수 있다.

### 5.1 검증 질문 먼저 만들기

```text
이 답변에서 반드시 사실 확인이 필요한 주장 5개를 먼저 추출해줘.
```

### 5.2 요소별 검증

```text
위 답변에서 숫자와 연도만 추출해서 검증 필요성을 표시해줘.
```

### 5.3 반론 생성

```text
이 답변이 틀렸다고 가정하고 가장 취약한 주장 3개를 찾아줘.
```

### 5.4 수정

```text
검증된 정보만 남겨 최종본을 다시 작성해줘.
```

> AI의 자기검증은 보조 수단이다. 사실 여부를 확정하려면 독립적인 외부 근거가 필요하다.

---

## 6. 실무 검증 워크플로우

```text
1. AI로 초안 생성
        ↓
2. 사실 주장 추출
        ↓
3. 숫자/연도/고유명사 분리
        ↓
4. 다른 모델 또는 검색으로 반론 탐색
        ↓
5. 공식 출처 확인
        ↓
6. 원문 확인
        ↓
7. 잘못된 내용 수정
        ↓
8. 인간이 최종 판단
```

### 공식 출처 예시

- 기업 정보 → 공식 IR, 공시
- 국내 통계 → KOSIS
- 기업 공시 → DART
- 법률 → 국가법령정보센터
- 논문 → 원 논문, 학술 데이터베이스
- 정부 정책 → 해당 정부 기관 공식 사이트

---

## 7. AI를 잘 쓰는 사람의 검증 습관

AI 활용 능력은 프롬프트를 잘 쓰는 것만으로 끝나지 않는다.

```text
질문 능력
+ 맥락 설계
+ 결과 검증
+ 인간의 판단
```

이 네 가지가 함께 있어야 실제 업무에서 신뢰할 수 있는 결과를 만들 수 있다.

특히 중요한 의사결정에서는 다음 질문을 반복해야 한다.

- 이 숫자의 출처는 무엇인가?
- 원문이 실제 존재하는가?
- 최신 정보인가?
- 다른 독립 출처도 같은 내용을 말하는가?
- AI가 사실과 해석을 섞어 말하고 있지 않은가?

## 핵심 연결 구조

```text
좋은 AI 활용

문제 정의
  ↓
Zero-shot / Few-shot 선택
  ↓
Role + Goal + Context/Constraint
  ↓
필요하면 단계적 추론 구조 추가
  ↓
출력 형식 지정
  ↓
AI 결과 생성
  ↓
SIFT + Micro Fact-Check
  ↓
공식 출처 및 원문 검증
  ↓
인간의 최종 판단
```

**프롬프트 엔지니어링의 핵심은 AI에게 잘 묻는 것이고, AI 리터러시의 완성은 그 답을 검증하고 최종 판단을 인간이 책임지는 것이다.**
