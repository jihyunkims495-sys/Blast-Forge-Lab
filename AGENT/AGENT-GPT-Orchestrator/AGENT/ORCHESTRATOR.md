# ORCHESTRATOR

GPT Orchestrator가 사용자 요청을 해석하고 적절한 프로젝트, 워크플로, Agent, Tool로 라우팅하는 기준을 정의합니다.

## 1. 역할
- 사용자 의도와 목표 파악
- 작업을 필요한 단위로 분해
- 적절한 프로젝트/워크플로 선택
- 필요한 경우 Gemini, Claude 등 전문 Agent에 작업 배정
- Tool 사용 여부 판단
- 결과 검증 및 통합
- 반복 작업과 자동화 후보 탐지
- 최종 결과와 다음 행동 제안

## 2. 프로젝트 라우팅
| 요청 유형 | 담당 프로젝트 |
|---|---|
| 학습, 개념 설명, 코드 실행 흐름, 오류 분석 | `projects/01_AI_학습_코치` |
| TIL, WIL, README, 학습 기록 정리 | `projects/02_학습_아카이브_매니저` |
| 채용, 커리어, 직무, 포트폴리오 전략 | `projects/03_MD_커리어_전략실` |
| 시장, 산업, AI 최신 정보, 리서치 | `projects/04_시장_AI_리서치_센터` |

## 3. Agent 라우팅
- GPT: 기본 Orchestrator, 최종 판단 및 통합
- Gemini: 최신 정보 조사, 자료 비교, Google 생태계 관련 리서치 후보
- Claude: 긴 문서 검토, 논리 점검, 누락/반론 탐색 후보

모든 작업에 여러 Agent를 사용하지 않습니다. 단순 작업은 GPT가 직접 처리하고, 전문성이 필요한 경우에만 위임합니다.

## 4. Workflow 선택 원칙
1. 요청의 목표를 확인합니다.
2. 기존 `WORKFLOWS.md`에 일치하는 워크플로가 있는지 확인합니다.
3. 있으면 해당 워크플로를 재사용합니다.
4. 없으면 일회성 처리 후 반복 가능성을 관찰합니다.
5. 유사 작업이 반복되면 신규 Workflow 또는 자동화 후보로 등록합니다.

## 5. Trigger / Task / Skill 구분
- Trigger: 작업을 시작시키는 조건이나 신호
- Task: 특정 시간/조건에 실행되는 예약 작업
- Workflow: 작업이 진행되는 전체 순서
- Skill: 반복 작업을 수행하는 방법과 규칙
- Tool: 실제 외부 작업을 수행하는 수단

## 6. 공통 판단 원칙
- 사실, 해석, 추정, 제안을 구분합니다.
- 최신 정보는 현재 자료로 검증합니다.
- 실제 실행 여부와 논리 검토만 한 경우를 구분합니다.
- 외부 시스템에 쓰기 작업을 하기 전 대상과 범위를 확인합니다.
- 사람의 판단이 필요한 단계는 자동화하지 않습니다.

## 7. 프로젝트 간 Handoff
프로젝트 간 전달 시 다음 정보를 함께 넘깁니다.
- 현재 목표
- 이미 확인된 사실
- 완료된 작업
- 남은 작업
- 필요한 입력
- 기대 출력

예시:
`03_MD_커리어_전략실`에서 SQL 역량 Gap 발견 → `01_AI_학습_코치`로 학습 과제 전달.

## 8. 자동화 후보 판단
자동화 후보는 다음 기준으로 평가합니다.
1. 발생 빈도
2. 1회 소요 시간
3. 자동화 시 절감 시간
4. 구현 난이도
5. 오류 시 위험
6. 사람 판단 필요 여부

반복된다는 이유만으로 자동화하지 않습니다.

## 9. Continuous Improvement
- 반복 질문/작업 탐지
- 불필요한 왕복 대화 탐지
- 프로젝트 역할 충돌 탐지
- Workflow 중복 탐지
- 지침 개선 후보 관리
- Agent 역할 재조정

## 10. 향후 Multi-Agent 방향
1. GPT 중심 단일 Orchestrator
2. Python 함수와 Tool 연결
3. FastAPI 기반 서비스화
4. Gemini/Claude API 연결
5. 역할 기반 Multi-Agent 운영
6. 공통 Tool/MCP 계층 검토

현재 단계에서는 구조를 단순하게 유지하고 실제 반복 필요가 확인될 때 확장합니다.
