# SYSTEM WORKFLOWS

여러 프로젝트를 넘나드는 시스템 수준의 Workflow를 관리합니다.

## 공통 필드
각 Workflow는 다음 항목을 가집니다.
- ID
- Status
- 목적
- Trigger
- Input
- 담당 Project
- Process
- Handoff
- Output
- 완료 조건
- 사람 승인 지점
- 자동화 범위
- 사용 Tool
- 예외 처리
- 개선 기록

## WF-001 — 일일 학습 파이프라인

**Status:** ACTIVE

### 목적
매일 교안 입력부터 학습, 평가, 최종 정리, TIL, GitHub 반영까지 하나의 학습 사이클로 운영합니다.

### Trigger
- 매일 오전 07:50 예약 Task
- 또는 사용자가 당일 교안을 먼저 전달

### Input
- 오늘 교안
- 수업 중 질문
- 작성 코드
- 오류 메시지
- 개인 메모
- 퀴즈 답안

### 담당 Project
1. `01_AI_학습_코치`
2. `02_학습_아카이브_매니저`

### Process
```text
07:50 Task
↓
오늘 교안 입력
↓
01_AI_학습_코치
├─ 교안 전체 분석
├─ 오늘 학습 전체 구조 작성
├─ 중요 개념 정리
├─ 상세 학습 노트 작성
├─ 수업 중 질문/코드/오류 누적
└─ 헷갈렸던 것 리뷰 업데이트
↓
사용자: "오늘 수업 끝"
↓
5지선다 + 서술형 혼합 문제 10개
↓
사용자 풀이
↓
채점 / 오답 원인 / 취약 개념 분석
↓
최종 개념 정리
↓
02_학습_아카이브_매니저
├─ TIL 작성
├─ 필요 시 README/WIL 연결
└─ GitHub 저장 구조 확인
↓
Blast-Forge-Lab 반영
↓
DONE
```

### 학습 평가 기준
- 문제 10개는 당일 핵심 개념 범위의 80% 이상을 커버하도록 설계
- 8/10 이상은 이해 양호 참고 기준
- 점수만으로 숙달을 단정하지 않음
- 오답 원인과 핵심 서술형 설명 가능 여부를 함께 확인

### Handoff
`01_AI_학습_코치` → `02_학습_아카이브_매니저`

전달 정보:
- 오늘 핵심 개념
- 헷갈렸던 내용
- 퀴즈 결과
- 오답 및 취약 개념
- 최종 개념 정리

### Output
- 당일 학습 Markdown
- 헷갈렸던 것 리뷰
- 퀴즈 및 채점 결과
- 최종 개념 정리
- TIL
- GitHub 반영 결과

### 완료 조건
- 당일 학습 평가 완료
- 최종 개념 정리 완료
- TIL 생성 완료
- 요청된 경우 GitHub 반영 성공 확인

### 사람 승인 지점
- 중요한 기존 파일 덮어쓰기
- 학습 구조 대규모 변경
- GitHub의 기존 문서 삭제/이동

### 자동화 범위
현재 자동화:
- 07:50 학습 파이프라인 시작 알림

대화 신호:
- 교안 전달 → 교안 분석 단계
- `오늘 수업 끝` → 평가 단계
- 답안 전체 제출 → 채점 단계

### 예외 처리
- 교안이 없으면 분석을 추정하지 않음
- 수업이 끝나지 않았으면 퀴즈를 강제 시작하지 않음
- GitHub 경로가 불명확하면 쓰기 전 확인

## WF-005 — README 버전 아카이브

**Status:** ACTIVE

### 목적
루트 `README.md`를 항상 최신 상태로 유지하면서, 큰 구조 변경 전의 중요한 버전을 사람이 쉽게 확인할 수 있도록 별도 보존합니다.

### Trigger
다음 조건 중 하나가 발생할 때 실행합니다.
- 저장소의 목적/방향 변경
- Agent 또는 Workflow 구조의 대규모 변경
- 포트폴리오 README 대규모 개편
- 개발 Phase 변경
- 사용자의 명시적 아카이브 요청

### Input
- 현재 루트 `README.md`
- 변경 예정 내용
- 아카이브 날짜/버전

### Process
```text
README 변경 요청
↓
현재 README 확인
↓
중대한 변경인가?
├─ NO → README만 수정
└─ YES
    ↓
현재 README를 archive/README/에 스냅샷 저장
    ↓
새 README 반영
    ↓
GitHub에서 아카이브와 최신 README 모두 확인
    ↓
DONE
```

### Output
- `archive/README/YYYY-MM-DD_vN.md` 또는 설명형 파일명
- 최신 루트 `README.md`

### 완료 조건
- 변경 전 README 아카이브 파일 존재 확인
- 최신 README 반영 확인

### 예외 처리
- 같은 이름의 아카이브 파일이 이미 있으면 덮어쓰지 않고 다음 버전 번호를 사용
- 오타/링크 등 경미한 변경은 아카이브 생성을 생략
