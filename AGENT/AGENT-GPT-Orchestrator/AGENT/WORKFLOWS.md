# SYSTEM WORKFLOWS

여러 프로젝트를 넘나드는 시스템 수준의 Workflow를 관리합니다.

## 공통 필드
각 Workflow는 다음 항목을 가집니다.
- ID
- Status
- 목적
- Trigger
- Input
- 담당 Project
- Process
- Handoff
- Output
- 완료 조건
- 사람 승인 지점
- 자동화 범위
- 사용 Tool
- 예외 처리
- 개선 기록

## WF-001 — 일일 학습 파이프라인

**Status:** ACTIVE

### 목적
매일 교안 입력부터 학습, 평가, 최종 정리, TIL, GitHub 반영까지 하나의 학습 사이클로 운영합니다.

### Trigger
- 매일 오전 07:50 예약 Task
- 또는 사용자가 당일 교안을 먼저 전달

### Input
- 오늘 교안
- 수업 중 질문
- 작성 코드
- 오류 메시지
- 개인 메모
- 퀴즈 답안

### 담당 Project
1. `01_AI_학습_코치`
2. `02_학습_아카이브_매니저`

### Process
```text
07:50 Task
↓
오늘 교안 입력
↓
01_AI_학습_코치
├─ 교안 전체 분석
├─ 오늘 학습 전체 구조 작성
├─ 중요 개념 정리
├─ 상세 학습 노트 작성
├─ 수업 중 질문/코드/오류 누적
└─ 헷갈렸던 것 리뷰 업데이트
↓
사용자: "오늘 수업 끝"
↓
5지선다 + 서술형 혼합 문제 10개
↓
사용자 풀이
↓
채점 / 오답 원인 / 취약 개념 분석
↓
최종 개념 정리
↓
02_학습_아카이브_매니저
├─ TIL 작성
├─ 필요 시 README/WIL 연결
└─ GitHub 저장 구조 확인
↓
Blast-Forge-Lab 반영
↓
DONE
```

### 학습 평가 기준
- 문제 10개는 당일 핵심 개념 범위의 80% 이상을 커버하도록 설계
- 8/10 이상은 이해 양호 참고 기준
- 점수만으로 숙달을 단정하지 않음
- 오답 원인과 핵심 서술형 설명 가능 여부를 함께 확인

### Handoff
`01_AI_학습_코치` → `02_학습_아카이브_매니저`

전달 정보:
- 오늘 핵심 개념
- 헷갈렸던 내용
- 퀴즈 결과
- 오답 및 취약 개념
- 최종 개념 정리

### Output
- 당일 학습 Markdown
- 헷갈렸던 것 리뷰
- 퀴즈 및 채점 결과
- 최종 개념 정리
- TIL
- GitHub 반영 결과

### 완료 조건
- 당일 학습 평가 완료
- 최종 개념 정리 완료
- TIL 생성 완료
- 요청된 경우 GitHub 반영 성공 확인

### 사람 승인 지점
- 중요한 기존 파일 덮어쓰기
- 학습 구조 대규모 변경
- GitHub의 기존 문서 삭제/이동

### 자동화 범위
현재 자동화:
- 07:50 학습 파이프라인 시작 알림

대화 신호:
- 교안 전달 → 교안 분석 단계
- `오늘 수업 끝` → 평가 단계
- 답안 전체 제출 → 채점 단계

### 예외 처리
- 교안이 없으면 분석을 추정하지 않음
- 수업이 끝나지 않았으면 퀴즈를 강제 시작하지 않음
- GitHub 경로가 불명확하면 쓰기 전 확인

## WF-005 — README 버전 아카이브

**Status:** ACTIVE

### 목적
루트 `README.md`를 항상 최신 상태로 유지하면서, 큰 구조 변경 전의 중요한 버전을 사람이 쉽게 확인할 수 있도록 별도 보존합니다.

### Trigger
다음 조건 중 하나가 발생할 때 실행합니다.
- 저장소의 목적/방향 변경
- Agent 또는 Workflow 구조의 대규모 변경
- 포트폴리오 README 대규모 개편
- 개발 Phase 변경
- 사용자의 명시적 아카이브 요청

### Input
- 현재 루트 `README.md`
- 변경 예정 내용
- 아카이브 날짜/버전

### Process
```text
README 변경 요청
↓
현재 README 확인
↓
중대한 변경인가?
├─ NO → README만 수정
└─ YES
    ↓
현재 README를 archive/README/에 스냅샷 저장
    ↓
새 README 반영
    ↓
GitHub에서 아카이브와 최신 README 모두 확인
    ↓
DONE
```

### Output
- `archive/README/YYYY-MM-DD_vN.md` 또는 설명형 파일명
- 최신 루트 `README.md`

### 완료 조건
- 변경 전 README 아카이브 파일 존재 확인
- 최신 README 반영 확인

### 예외 처리
- 같은 이름의 아카이브 파일이 이미 있으면 덮어쓰지 않고 다음 버전 번호를 사용
- 오타/링크 등 경미한 변경은 아카이브 생성을 생략

## WF-006 — 학습정리 파일명 및 GitHub 커밋 승인

**Status:** ACTIVE

### 목적
학습정리 Markdown 파일의 이름을 일관되게 유지하고, GitHub 커밋 전에 사용자가 변경 범위와 커밋 메시지를 반드시 점검할 수 있도록 합니다.

### 학습정리 파일명 규칙

기본 형식:

```text
[Python]_<한글주제>_학습정리.md
```

예시:

```text
[Python]_조건문_학습정리.md
[Python]_모듈과-패키지_학습정리.md
[Python]_객체지향-클래스-상속-캡슐화_학습정리.md
```

세부 규칙:
- 파일명 앞에는 학습 언어를 대괄호 말머리로 표기합니다. 현재 Python 학습은 `[Python]`을 사용합니다.
- `[Python]` 뒤에는 `_`를 하나 넣습니다.
- 날짜는 파일명에 넣지 않습니다. 날짜는 상위 날짜 폴더가 담당합니다.
- 주제는 가능한 한 한글 중심으로 작성합니다.
- 마지막에는 `_학습정리.md`를 붙입니다.
- 같은 날짜 폴더 안에서도 파일명만 보고 어떤 언어와 주제의 학습정리인지 식별할 수 있어야 합니다.

### 커밋 메시지 규칙

기본 형식:

```text
<type>: <변경 내용>
```

주요 type:
- `docs:` 학습정리, TIL, README 등 문서 추가/수정
- `feat:` 새로운 기능 추가
- `fix:` 오류 수정
- `refactor:` 기능 변화 없이 구조 개선
- `chore:` 설정, 정리, 유지보수 작업

예시:

```text
docs: add Python 조건문 학습정리
docs: standardize Python study note filenames
fix: correct Python example indentation
```

### 커밋 전 승인 절차

```text
파일 생성 또는 수정
↓
저장 경로 확인
↓
파일명 규칙 확인
↓
변경 파일 목록 확인
↓
커밋 메시지 초안 작성
↓
사용자에게 사전 점검 요청
↓
사용자 승인
↓
commit / push
```

### 사람 승인 지점
- 모든 GitHub commit / push 직전

승인으로 인정할 수 있는 명시적 표현 예:
- `커밋해`
- `올려`
- `승인`
- 해당 변경 내용에 대한 명확한 동의 표현

### 금지 규칙
- 사용자의 사전 승인 없이 commit 또는 push하지 않습니다.
- 파일명 규칙과 맞지 않는 학습정리 파일은 그대로 커밋하지 않고 먼저 수정안을 제시합니다.
- 커밋 메시지는 임의로 확정하지 않고 커밋 전에 사용자에게 보여줍니다.

### 자동화 범위
다음 항목은 매번 자동 점검합니다.
1. 학습정리 파일에 `[Python]_` 말머리가 있는지
2. 날짜가 파일명에 중복 포함되지 않았는지
3. 한글 주제가 파일명에 드러나는지
4. `_학습정리.md`로 끝나는지
5. 커밋 type이 변경 성격과 일치하는지
6. 사용자 승인 여부가 확인되었는지

### 예외 처리
- 사용자가 특정 파일명 또는 커밋 메시지를 명시적으로 지정하면 그 요청을 우선합니다.
- 기존 저장소 규칙과 충돌하는 요청이 나오면 임의 변경하지 않고 차이를 설명한 뒤 확인합니다.
- 외부에서 직접 수행된 커밋은 이 Workflow로 사전 차단할 수 없습니다. 이 규칙은 ChatGPT가 수행하는 GitHub 작업에 적용합니다.
